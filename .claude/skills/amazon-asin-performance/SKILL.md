# amazon-asin-performance

تحليل عميق لأداء ASIN أو مجموعة ASINs — يكشف سبب الأداء الجيد أو السيئ
ويعطي توصيات محددة لكل منتج.

## متى تُفعَّل
عند طلب "حلل هذا المنتج"، "ASIN analysis"، "ليش هاد المنتج ما بيبيع"،
"قارن بين ASINs"، "أداء المنتجات".

## المدخلات
- ملف Business Report يحتوي بيانات الـ ASIN
- أو إدخال ASIN يدوياً مع البيانات المتاحة
- يمكن تحليل ASIN واحد أو حتى 50 ASIN دفعة واحدة

## مراحل التحليل

### المرحلة 1: تشخيص الصحة العامة للـ ASIN

لكل ASIN، احسب "درجة الصحة" من 100:

```
معدل التحويل (Unit Session %):     [0-30 نقطة]
  > 15%    → 30 نقطة (ممتاز)
  10-15%   → 20 نقطة (جيد)
  5-10%    → 10 نقطة (متوسط)
  < 5%     → 0 نقطة (ضعيف)

Buy Box %:                          [0-25 نقطة]
  > 90%    → 25 نقطة
  70-90%   → 15 نقطة
  50-70%   → 5 نقطة
  < 50%    → 0 نقطة

الزيارات (Sessions):               [0-25 نقطة]
  مقارنة بمتوسط الفئة المقدّر

المخزون:                           [0-20 نقطة]
  متاح > 30 يوم → 20 نقطة
  15-30 يوم     → 10 نقطة
  < 15 يوم      → 0 نقطة
```

### المرحلة 2: تحديد المشكلة الجذرية

**إذا الزيارات منخفضة + التحويل عادي:**
→ مشكلة في Discoverability (SEO، إعلانات، رتبة البحث)

**إذا الزيارات عالية + التحويل منخفض:**
→ مشكلة في Listing (صور، عنوان، سعر، تقييمات)

**إذا الزيارات عالية + التحويل عالي + المبيعات منخفضة:**
→ مشكلة في المخزون أو Buy Box

**إذا الكل منخفض:**
→ مشكلة مركّبة تحتاج تدخلاً شاملاً

### المرحلة 3: مقارنة ASIN بنفسه عبر الزمن

إذا توفرت بيانات تاريخية:
- أفضل أسبوع/شهر له ومتى كان؟
- ما الذي تغيّر منذ ذلك الحين؟
- هل التراجع تدريجي أم مفاجئ؟ (المفاجئ يشير لحدث محدد)

### المرحلة 4: التوصيات المحددة

لكل مشكلة مكتشفة، أعطِ:
```
المشكلة:    [وصف محدد]
الدليل:     [رقم من البيانات]
الإجراء:    [ماذا تفعل بالضبط]
الأولوية:   [عاجل / هذا الأسبوع / هذا الشهر]
التأثير المتوقع: [تقدير محافظ]
```

## قواعد صارمة
- لا تقل "الـ listing يحتاج تحسين" بدون تحديد أي جانب بالضبط
- التوصيات مرتّبة حسب الأثر المتوقع، ليس الصعوبة
- لا تفترض رتبة BSR أو بيانات منافسين غير موجودة في الملف
